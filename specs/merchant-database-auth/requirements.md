# 商家数据库账号登录与测试数据需求

## 背景

当前网页版和微信小程序端使用同一个 `adminKey` 作为商家管理口令，口令由云函数环境变量提供。该方式不具备商家用户名、密码变更、会话失效和账号停用能力。本次改造需要将商家身份改为 CloudBase 数据库配置，并让两端共用同一套登录和权限校验逻辑。

## 目标

1. 商家使用“用户名 + 密码”登录网页版或小程序商家端。
2. 密码不得以明文形式保存在数据库、代码、配置文件、接口响应或日志中。
3. 登录成功后由云函数签发有时效的随机会话令牌，数据库只保存令牌摘要。
4. 所有商家管理操作统一验证数据库会话，不再接受旧的 `ADMIN_ACCESS_KEY` 或 `adminKey` 作为管理凭证。
5. 初始化 CloudBase PostgreSQL 数据表，并以幂等方式写入可识别的测试数据，不覆盖已有业务数据。

## 功能需求

### 1. 商家账号

- 系统应提供 `merchant_accounts` 集合保存商家账号。
- 商家账号应至少包含用户名标准化值、显示名称、密码哈希、密码盐、哈希算法版本、启用状态、首次登录改密标记、创建时间、更新时间和最后登录时间。
- 用户名比较应忽略首尾空格和英文字母大小写。
- 停用账号不得登录，也不得继续使用已有会话。
- 首个商家账号默认使用用户名 `admin`，密码采用已确认的一次性临时密码，并在首次登录后要求修改。

### 2. 密码与会话安全

- 云函数应使用 Node.js 内置安全密码派生算法和随机盐保存密码哈希。
- 云函数应使用恒定时间比较校验密码摘要。
- 系统应提供登录、退出登录和修改密码能力。
- 登录成功后应返回随机会话令牌；令牌有效期默认 12 小时。
- `merchant_sessions` 集合只能保存会话令牌摘要、关联账号、有效期、撤销时间、创建时间和最后使用时间。
- 网页端和小程序端不得持久化或回显商家密码；页面关闭或小程序退出后允许要求重新登录。
- 接口响应和日志不得返回密码哈希、密码盐、完整会话令牌摘要或 CloudBase 运行时敏感信息。

### 3. 双端商家登录

- 网页端商家模块应提供用户名和密码登录界面，并在登录成功后加载云端订单、商品、店铺和收款设置。
- 小程序商家模块应提供相同的用户名和密码登录界面，并使用同一 CloudBase 云函数完成登录。
- 两端登录失败时应显示明确但不泄露账号是否存在的统一提示。
- 会话过期、被撤销或账号停用后，两端应退出商家状态并要求重新登录。
- 两端退出登录时应撤销当前会话并清除内存中的令牌。

### 4. 商家权限保护

- 查询全部订单、更新订单、保存商品、保存店铺设置、保存收款码和上传商家图片等管理操作应验证有效商家会话。
- 顾客使用订单访问令牌查询自己的订单、提交订单和读取公开店铺信息的能力应保持不变。
- 旧的 `ADMIN_ACCESS_KEY`、请求头 `x-admin-key` 和请求参数 `adminKey` 不得继续作为 CloudBase 商家管理授权方式。

### 5. CloudBase PG 表与测试数据

- 系统应初始化现有业务表：`products`、`orders`、`store_settings`、`payment_methods`、`order_counters`。
- 系统应新增认证表：`merchant_accounts`、`merchant_sessions`。
- 测试商品应至少包含 6 条可售商品，覆盖包子、馒头和饮品等分类。
- 测试订单应至少包含 1 条到店自提订单和 1 条配送到家订单，并覆盖取餐号、配送费及订单状态字段。
- 测试收款设置应至少包含 2 条收款码配置，包含名称、备注、启用状态和排序字段；二维码内容必须标记为测试占位内容，不能让顾客误付款。
- 测试店铺配置应包含配送范围、配送费、免配送费门槛和最低起送金额。
- 初始化过程应使用稳定主键并只补充缺失数据，不覆盖已经由商家维护的数据。

## 验收标准

1. 当商家输入正确的用户名和密码时，网页端和小程序端都应登录成功，并能执行受保护的商家操作。
2. 当用户名或密码错误时，系统应拒绝登录并返回统一错误提示，且数据库和日志中不出现明文密码。
3. 当会话过期、撤销或关联账号被停用时，所有受保护操作应被拒绝，两端应提示重新登录。
4. 当请求继续携带旧 `adminKey` 或 `x-admin-key` 时，系统不得据此授予商家权限。
5. 当初始化命令重复执行时，已有商品、订单、店铺和收款设置不得被覆盖或重复创建。
6. 当数据库初始化完成时，CloudBase 中应存在 7 张目标表、首个商家账号及上述测试数据。
7. 当顾客从任一端下单时，原有自提、配送、取餐号、配送费和个人收款码流程应保持可用。

## 非目标

- 本次不实现多角色权限、员工权限分组、短信找回密码或第三方单点登录。
- 本次不接入微信支付或其他自动支付接口，仍使用商家配置的个人收款码。
- 本次不把商家密码交给 CloudBase 前端 SDK 直接校验，所有密码与会话逻辑均由现有 Event 云函数处理。

## 待确认项

- 首个商家账号采用用户名 `admin`、已确认的一次性临时密码、首次登录强制改密。
- 会话有效期采用 12 小时，网页端和小程序端仅在当前运行期间保存会话令牌。
