# 四级角色与可配置登录会话需求

## 目标

- 商家后台默认登录有效期为 30 分钟，刷新网页或重新打开小程序时可以恢复未过期会话。
- 系统提供超级管理员、普通管理员、商家、顾客四个权限等级。
- 超级管理员和普通管理员可以修改全局登录有效期，其他角色不能修改。
- 所有权限由 `ordering-api` 在服务端强制校验，前端隐藏入口不能代替鉴权。

## 角色规则

1. `super_admin`：拥有全部经营、账号、角色和系统设置权限。
2. `admin`：拥有全部经营权限，可以管理商家和顾客账号及会话时长，但不能修改超级管理员账号、授予管理员级角色或操作同级管理员。
3. `merchant`：可以处理订单、备货、商品、收款码和店铺配置，不能管理账号、角色或会话时长。
4. `customer`：只能使用顾客点单、个人资料和本人订单能力，不能进入商家后台。

## 会话规则

- 全局会话时长默认 30 分钟，允许设置为 5 至 1440 分钟。
- 会话从登录成功时固定计时，不因刷新或重新打开应用而丢失，也不因访问接口自动无限续期。
- 网页端只持久化随机会话令牌、公开账号信息和到期时间；小程序端保存同等信息。
- 数据库只保存会话令牌的 SHA-256 摘要。
- 会话到期、主动退出、修改密码、账号停用或角色变更后，受保护接口必须拒绝访问。

## 验收标准

- 当旧 `admin` 账号完成迁移时，系统应将其角色设置为 `super_admin`。
- 当任一后台账号登录成功时，系统应按当前数据库配置签发固定有效期会话。
- 当页面刷新或小程序重新启动且会话仍有效时，两端应恢复后台登录状态。
- 当会话已经过期或撤销时，两端应清除本地会话并要求重新登录。
- 当 `super_admin` 或 `admin` 修改会话时长时，新登录会话应使用新值，已有会话保持原到期时间。
- 当低权限账号调用无权接口时，服务端应返回 403，且数据不得发生变化。
- 当管理员修改账号角色、停用账号或重置密码时，该账号已有会话应全部撤销。
- 当顾客继续下单、查询本人订单或提交付款信息时，现有流程应保持兼容。

## 非目标

- 本次不新增顾客注册和密码登录；顾客继续免登录点单。
- 本次不接入第三方单点登录、短信找回密码或微信支付。
- 本次不把 CloudBase API Key 或密码摘要暴露给网页、小程序或日志。
